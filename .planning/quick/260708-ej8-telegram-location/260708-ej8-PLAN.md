<objective>
Add a "Location:" line to the Telegram account card, derived from the account's phone dial code. Backend computes the location on the fly from `Sender.phone` (E.164, stored with leading `+`) using a small custom dial-code lookup table (NO `phonenumbers` dependency — user decision D-01) and surfaces it as a new `location` field on `SenderResponse`. Frontend displays it under the phone.

Purpose: Managers running multi-account outreach need to see at a glance which country/region each connected account belongs to, without opening Telegram.

Output:
- Backend: `app/utils/location.py` lookup module + tests, `location` field on `SenderResponse`, regenerated `lovable-handoff/openapi.json`.
- Frontend (separate sibling repo): `Location:` line in the account card + detail modal, OpenAPI/type sync.

This is a two-repo change. Tasks 1–3 are the "quick task" proper in THIS repo (tg-outreach). Task 4 edits the SEPARATE frontend repo and commits there independently — see the cross-repo git rules in Task 4.
</objective>

    - "+79001234567"  → "Russia"           (mobile +79…)

    - "+380501234567" → "Ukraine"
    - "+375291234567" → "Belarus"
    - "+15551234567"  → "US/Canada"         (+1 is shared NANP)
    - "+442071234567" → "United Kingdom"
    - "+998901234567" → "Uzbekistan"        (longest-prefix match beats a shorter code)
    - "+9990001"      → "Unknown" or None    (no matching dial code → graceful fallback)
    - "abc" / "" / None → None               (malformed / empty → None, no crash)
    - "+1" (code only, no subscriber digits) → still resolves to "US/Canada" (prefix match)
  </behavior>
  <action>
    Create a NEW module `app/utils/location.py` (keep it separate from phone.py — phone.py's
    single concern is E.164 normalization + identity keys; a large dial-code table belongs
    in its own module). Follow phone.py's style: pure Python, NO external libraries — do NOT
    add `phonenumbers` (user decision D-01, and CLAUDE.md/phone.py already forbid it).

    Implement:
      def phone_location(phone: Optional[str]) -> Optional[str]:
        - Strip to digits; if the input had no leading '+' or is empty/non-numeric → return None
          (reuse the same guard idea as phone.py: an E.164 sender phone always starts with '+').
          Simplest robust rule: require the raw string to start with '+' and contain only
          digits after stripping formatting; otherwise return None.
        - Longest-prefix match against a DIAL_CODES dict mapping dial code (digits, no '+')
          → location label. Match by trying the longest candidate prefixes first (3-digit,
          then 2-digit, then 1-digit) so "+380" beats "+3" and "+998" beats "+9".
        - +7 sub-rule (ambiguous Russia/Kazakhstan): if code == "7", inspect the FIRST national
          digit (the digit right after "7"): '6' or '7' → "Kazakhstan", otherwise → "Russia".
          Document this as an approximate heuristic (KZ mobile ranges start 6/7, RU mobile 9).
        - +1 → "US/Canada" (shared NANP — do not try to split states/provinces).
        - No match → return "Unknown" (a stable string is friendlier for the UI than None here;
          reserve None strictly for malformed/empty input). Document this distinction.

    DIAL_CODES table: cover at least ~40-50 of the most common country codes with a bias toward
    the outreach platform's client base. MUST include: 7 (Russia/Kazakhstan via sub-rule),
    380 (Ukraine), 375 (Belarus), 1 (US/Canada), 44 (United Kingdom), plus CIS neighbours
    (374 Armenia, 994 Azerbaijan, 995 Georgia, 996 Kyrgyzstan, 992 Tajikistan, 993 Turkmenistan,
