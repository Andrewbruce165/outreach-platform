# Quick Task 260629-ig7: Re-render pending queue on template change

## Goal

Close the footgun where editing a running campaign's `message_template` leaves
already-`pending` `message_queue` rows carrying the OLD rendered opener (the queue
snapshots rendered text at enqueue time — see
[[project-queue-snapshots-template-at-enqueue]]). After this task, a template edit
propagates to pending items automatically (PATCH hook) and on demand (endpoint).

Decision (user-confirmed): auto on PATCH **and** explicit endpoint, sharing one helper.

## Tasks

### Task 1 — `rerender_pending_queue(db, campaign) -> int` helper
- New function in `app/services/campaign_enqueue.py` (reuses `render_template` +
  `contact_identity_key` already imported there).
- Re-renders `message_text` of all `status='pending'`, `item_type='message'` rows for
  the campaign using the CURRENT `campaign.message_template`, matching each row to its
  contact by identity (`recipient_phone == COALESCE(phone,'@'||username)`) in the
  campaign folder so `{{vars}}` render with the same data the enqueue worker used.
  Fallback to a minimal contact (`recipient_name` + phone) when the contact is no
  longer in the folder (moved/deleted).
- `UPDATE … WHERE id=:id AND status='pending'` per row (re-checks status so a row the
  worker sent meanwhile is skipped). Does NOT commit — caller owns the txn. Empty
  template → no-op (never blank a message). Returns count updated.
- verify: unit test renders new text for pending, leaves sent untouched, handles vars + fallback.

### Task 2 — endpoint + PATCH hook
- `POST /campaigns/{campaign_id}/rerender-pending` (workspace-scoped via `_load_campaign`),
  returns `{rerendered: int}` (inline `_RerenderResponse`). Commits.
- `patch_campaign`: when `message_template` is present in the PATCH and differs from the
  stored value, call the helper after the setattr loop, before commit (atomic with the
  template change). Log the count (WarningItem is numeric-only, so no response warning).
- verify: PATCH that changes template re-renders pending; PATCH that doesn't leaves them; endpoint works + 404 cross-workspace.

### Task 3 — tests (test-overlay only)
- Helper unit test + router tests (endpoint + PATCH auto-hook). Run:
  `docker compose -f docker-compose.yml -f docker-compose.test.yml run --rm api pytest tests/...`

### Task 4 — commit, SUMMARY, STATE row, deploy
- Atomic commits; SUMMARY.md; STATE Quick Tasks row; deploy api (`up -d --build api`).

## must_haves
- truths:
  - editing message_template propagates to pending rows (auto + on-demand).
  - sent rows are never touched; empty template never blanks a message.
  - vars render from the contact; fallback to stored name when contact is gone.
- artifacts: rerender_pending_queue helper, rerender-pending endpoint, PATCH hook, tests.
