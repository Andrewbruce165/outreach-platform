# Quick 260701-px7 — Attach Decodo ISP socks5 proxies to all senders

**Type:** ops (prod DB data change + service restart — no code, no migration)
**Date:** 2026-07-01

## Задача

Привязать обновлённый пул Decodo ISP-прокси (`isp.decodo.com`, socks5, порты 10001–10020,
логин `spexuz82nw`) ко всем 16 аккаунтам в таблице `senders`. До этого у всех
`proxy = 'null'::jsonb` (прямой коннект).

## Контекст / предыстория

Предыдущая партия РФ-socks5-прокси (194.226.x / 46.161.x / 83.171.x / 185.42.x / 193.150.x)
была **отвергнута**: эмпирическая проба показала, что до нейтрального `1.1.1.1:443` коннект
есть у всех 8, но **ни один не достаёт серверы Telegram** (DC1/2/4/5 на :443 и :80 → SOCKS
`0x01 General SOCKS server failure` либо timeout). Привязка вывела бы из строя все +7-аккаунты.
Провайдеру отправлен запрос. Взамен пришёл рабочий пул Decodo.

## Проверки перед записью (read-only)

1. **Тип:** порт 10001 работает и по socks5, и по http; проект канонично использует socks5
   (`app/routers/onboarding.py:158`, `_PROXY_TYPE_MAP` в `app/services/telegram.py`).
2. **Достижимость Telegram:** все 20 портов через socks5 → Telegram DC2 (`149.154.167.51:443`) = OK.
3. **Уникальный IP на порт:** внешний IP каждого порта различается (US ISP-диапазоны:
   66.93.x, 12.12.x, 72.245.x, 216.132.x, 208.240.x, 198.145.x, 66.227.x, 94.154.x).
   ⚠️ IP американские — RU (+7) аккаунты логинятся с US-IP. По истории проекта ось
   доверия — прогрев/здоровье, не страна (Phase 17 D-10, memory
   `project-us-senders-cannot-resolve-ru-phones` — country claim REFUTED).

## Шаги

1. `backup.sh` (pg_dump) перед изменением.
2. `UPDATE senders SET proxy = jsonb_build_object('type','socks5','host','isp.decodo.com',
   'port', <10000+row_number over (order by created_at,id)>, 'username','spexuz82nw',
   'password', '***')` — детерминированный маппинг порт↔аккаунт, порты 10001–10016.
   10017–10020 в резерве.
3. `docker compose restart api listener` — форсить переподключение живых Telethon-клиентов
   через прокси (изменение только в БД, ребилд не нужен).
4. Верификация: TCP-соединения контейнеров идут к Decodo (`185.111.111.x`) на портах 100xx,
   не напрямую к `149.154.x`.

## Revert

```sql
UPDATE senders SET proxy = 'null'::jsonb;  -- вернуть прямой коннект
```
затем `docker compose restart api listener`. Либо restore из
`/root/backups/tg-outreach/outreach_20260701_114445.sql.gz`.
