# Quick Task 260630-e02 — Delete chats from UI

## Goal
Дать пользователю удалять диалоги из инбокса: (1) конкретный чат, (2) массово
через выделение нескольких. Удаление — hard delete (как существующий
`DELETE /conversations/{id}`: каскадом сносит беседу + сообщения + LLM-лог из
нашей БД; Telegram-диалог не затрагивается).

## Existing state
- BE: `DELETE /api/v1/conversations/{id}` (hard delete, workspace-scoped, 404 cross-ws) уже есть. Батча нет.
- BE precedent: `POST /api/v1/contacts/delete` (`{contact_ids:[…]}` → `{deleted:N}`, workspace-scoped, cross-tenant ids молча пропускаются) + `DeleteContactBatchRequest` в `app/schemas/__init__.py`.
- FE: `inbox.tsx` → `ConvList` (flex-список div'ов), state `selectedId`. TanStack Query (`["conversations"]`), `api()` wrapper умеет DELETE/POST, sonner `toast`, shadcn `AlertDialog`, `lucide-react`.
- FE precedent: `contacts.tsx` уже реализует ровно этот паттерн (`selected: Set<string>`, `allVisibleSelected`, bulk-bar, `POST /contacts/delete`, toast, `Trash2`).

## Tasks

### Task 1 — Backend batch endpoint (repo: tg-outreach)
- `app/schemas/__init__.py`: добавить `class DeleteConversationsBatchRequest(BaseModel)` с `conversation_ids: List[UUID] = Field(..., min_length=1)`.
- `app/routers/conversations.py`: добавить `POST /api/v1/conversations/delete` (`delete_conversations_batch`) — workspace-scoped raw-SQL `DELETE … WHERE id = ANY(:ids) AND workspace_id = :wid RETURNING id`, вернуть `{"deleted": N}`. Cross-tenant ids молча пропускаются (как contacts). Зарегистрировать в docstring-шапке router'а.
- Маршрут `/delete` объявить **до** `DELETE /{conversation_id}` уже неважно (разные HTTP-методы), но POST статический путь не конфликтует с `{id}`.
- **verify:** `POST /conversations/delete` удаляет только свои; чужие ids не трогают чужой workspace; вернёт корректный `deleted`.
- **done:** эндпоинт + схема на месте, тест зелёный.

### Task 2 — Backend test (repo: tg-outreach)
- `tests/test_phase5_inbox.py`: добавить `test_delete_conversations_batch_happy_path` (создать 2-3 conv, удалить 2, assert `deleted==2`, оставшийся жив) и `test_delete_conversations_batch_cross_workspace_skipped` (чужой id молча пропускается, не удаляется).
- **verify:** `docker compose -f docker-compose.yml -f docker-compose.test.yml run --rm api pytest tests/test_phase5_inbox.py -q` зелёный.
- **done:** новые тесты проходят, регрессий нет.

### Task 3 — Frontend single + bulk delete UI (repo: aimly-tg-outreach)
- `src/routes/_authenticated/inbox.tsx`:
  - `InboxPage`: state `selectionMode: boolean`, `selectedIds: Set<string>`, `pendingDelete` (single|bulk|null).
  - Мутации: `deleteOneMut` (`DELETE /conversations/{id}`), `deleteBulkMut` (`POST /conversations/delete`, body `{conversation_ids}` → `{deleted}`). onSuccess: invalidate `["conversations"]`, `toast.success`, очистить `selectedId` если удалён текущий, очистить выделение/выйти из режима (bulk).
  - Один контролируемый `AlertDialog` на уровне `InboxPage`, управляется `pendingDelete`.
  - `ConvList` (новые props): `selectionMode`, `selectedIds`, `onToggleSelectionMode`, `onToggleSelect`, `onToggleSelectAll`, `onRequestDeleteOne`, `bulkPending`, `onRequestDeleteBulk`.
    - Toolbar: кнопка «Select» (⇄ «Cancel»). В режиме — bulk-bar: [select-all] «N selected» [Delete (N)] [Cancel].
    - Ряд: в обычном режиме — иконка `Trash2` по hover (stopPropagation, открывает single-confirm); в режиме выделения — `checkbox` слева, клик по ряду тогглит выделение (не открывает диалог).
- **verify:** `bunx tsc --noEmit` без ошибок; визуально иконка+чекбоксы+bulk-bar появляются.
- **done:** одиночное и массовое удаление работают через UI, список обновляется, тосты показываются.
