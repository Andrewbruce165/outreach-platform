Fix Batch A of the 2026-07-03 checker/campaign review — the checker "lie detectors" that Phase 14 relied on. Two critical holes (CR-01, CR-02) reanimate the Phase-14 root bug: false negatives finalized as `not_registered / tg_confidence=high / tg_probe_state=clean`, silently discarding live leads. Plus two provenance/dead-code fixes (IN-01 wires the already-built `probe_control`; IN-08 stops cached hits stamping false resolver identity).

Purpose:
- **CR-01/IN-01:** `probe_checker` and `_recover_checkers` currently probe through `check_phones`, which reads AND writes `contacts_cache`. A probe that reads the cache tests nothing (a throttled checker "passes" on stale cached hits), and one bad live resolve of a control number cached `is_registered=false` can cascade-park the entire checker pool for up to 7 days. The correct live-only primitive `CheckerService.probe_control` (checker.py:305) exists but is never called. Wire it.
- **CR-02:** `_is_throttle_signal` gates its all-empty anomaly on `summary['registered'] == 0`, but `registered` is computed over ALL results including cache hits. A throttled batch of 20+ false live resolves + 2 cached positives escapes detection → 20+ false negatives finalized at high confidence. Judge the anomaly from live results only.
- **IN-08:** cache-served results finalize with `tg_resolved_by=<current checker>`, claiming a checker resolved live what it actually served from another sender's cache row. Stamp NULL for cache hits.
