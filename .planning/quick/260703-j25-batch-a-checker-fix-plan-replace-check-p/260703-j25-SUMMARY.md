# Quick 260703-j25: Batch A Checker Fix Summary

Closed the two critical holes (CR-01, CR-02) that reanimated the Phase-14 root bug —
false negatives finalized as `not_registered / tg_confidence=high / tg_probe_state=clean`

false resolver identity).

## The four (plus one collateral) edits

1. **`checker.py::probe_control` (IN-01 support).** Track a local `flood_wait_hit`
   (set True in the `except FloodWaitError` branch; the existing `asyncio.sleep` is
   untouched — WR-05 is Batch B) and add it to the return:
   `{"checked", "results", "flood_wait_hit"}`. This lets the caller classify a
   flood-interrupted probe as a miss instead of clean.

2. **`contact_check_worker.py::probe_checker` (CR-01/IN-01).** Swapped the
   cache-consulting `check_phones` call for the LIVE-ONLY `probe_control`
   (`checker_slug`/`encrypted_session`/`phones`/`proxy` only). MISS classification now
   fires on flood **or** truncation (`len(results) < len(sample)`) **or** any-negative
   **or** empty — a flood/short/empty probe proves nothing about health and is never
   treated as clean. Kills the cascade-park vector where one bad live resolve of a
   control number cached `is_registered=false` and failed the whole pool for ≤7 days.

3. **`contact_check_worker.py::_recover_checkers` (CR-01).** Same `check_phones →
   probe_control` swap for the recovery probe, and a strict clean test:
   `not flood AND len(results)==len(sample) AND results AND all(registered)`. A
   flood/truncated recovery probe can no longer fake-recover a still-throttled checker.

4. **`contact_check_worker.py::_is_throttle_signal` (CR-02).** Dropped the
   `summary["registered"] == 0` pre-condition. The all-empty anomaly is now judged
   from LIVE (`from_cache=False`) results only: `not any(is_registered for r in live)`.
   A poisoned batch of 20+ false live negatives plus a couple of cache-served positives
   (so `registered > 0`) — which previously escaped detection and finalized 20+ false
   negatives at high confidence — is now caught and rolled back to suspect.

5. **`contact_check_worker.py::_apply_results` (IN-08).** Added a per-result
   `resolver = None if res.get("from_cache") else checker_id` and bound `:resolver` in
   all three provenance branches (registered / suspect / clean-not_registered). A
   cache-served result now stamps `tg_resolved_by=NULL` (it was resolved from another
   sender's cache row, not live by this checker) so D-09 resolver-provenance forensics
   aren't corrupted. (`tg_resolved_by` is UUID NULL — mig 034; no migration needed.)
