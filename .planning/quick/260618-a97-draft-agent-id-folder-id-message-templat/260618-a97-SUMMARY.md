# Quick Task 260618-a97 — Summary

**Task:** Разрешить сохранять неполный draft кампании при создании. Сделать
`agent_id` / `folder_id` / `message_template` опциональными для драфта, а проверку
обязательных полей перенести на запуск (`POST /campaigns/{id}/start`).

Это backend-enabler для фронтового автосохранения драфта после каждого шага
7-шагового визарда (UI-SPEC §5.5): фронт делает `POST /campaigns` со `status=draft`
на шаге 1 (только name+brief) и `PATCH` на последующих шагах, не получая 422.

## Что изменено

- **`migrations/024_campaign_draft_nullable.sql`** — идемпотентный `ALTER TABLE
  campaigns ALTER COLUMN agent_id/folder_id DROP NOT NULL`. FK RESTRICT сохранён.
  `message_template` не трогается (остаётся `NOT NULL server_default ''`).
- **`app/models/__init__.py`** — `Campaign.agent_id` / `folder_id` → `nullable=True`.
- **`app/schemas/__init__.py`** — `CampaignCreate`: `agent_id` / `folder_id` /
  `message_template` теперь `Optional`. `CampaignResponse`: `agent_id` / `folder_id`
  → `Optional` (иначе сериализация драфта с NULL падала бы).
- **`app/routers/campaigns.py`**
  - `create_campaign`: ownership-валидация agent/folder вызывается только когда
    значение не `None`; `message_template or ""`.
  - `_campaign_to_response` / `_compute_is_exhausted`: None-safe — при `folder_id is
    None` возвращается `is_exhausted=False` (короткое замыкание, без бессмысленного SQL).
  - `start_campaign`: добавлен readiness-guard — перед `draft→running` проверяются
    `agent_id`, `folder_id` (NOT NULL) и непустой `message_template`; если чего-то нет
    → `HTTPException 422` с кодом `CAMPAIGN_INCOMPLETE` и списком недостающих полей.
    Существующая проверка ≥1 sender + sender-lock сохранена.
- **`tests/test_campaign_draft_optional.py`** — 4 новых теста: (a) POST без
  agent/folder/template создаёт draft 201; (b) `/start` на неполном драфте → 422
  `CAMPAIGN_INCOMPLETE`; (c) `/start` на дозаполненном через PATCH драфте → running;
  плюс кейс частичного драфта.
