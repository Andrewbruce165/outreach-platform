# Campaign Detail (`/campaigns/:id`) — бриф на редизайн

## Что есть сейчас

Плоская страница без вкладок (2 колонки + модалка Edit).

- **Шапка:** название, статус, pool health badge, кнопки Start/Pause/Resume/Stop/Edit
- **Слева:** Funnel-карточка (4 KPI: Chats/Replied/Leads/Finished), карточка с текстом шаблона сообщения, триггеры/вебхуки
- **Справа:** Overview (агент, папка, описание, цель, аргументы, правила), Schedule, Senders-панель (пилюли: имя/телефон/restriction-бейдж/lock)
- **Edit-модалка:** вся конфигурация одной длинной формой без табов (контент, вложения-альбом, расписание, follow-up, webhooks)

## Проблемы

1. **Нет логов/таймлайна** — совсем непонятно, что происходило с кампанией: когда паузили/запускали, кого отключали, какие были ограничения, когда пошли лиды. Главная жалоба.
2. Funnel показывает только 4 метрики из ~7 доступных, воронка не визуализирована
3. Senders-панель — просто пилюли, без health/лимитов/динамики по каждому отправителю
4. Нет превью вложений на самой странице (только в Edit)
5. Нет loading/error states — тихие фоллбэки на `0`/`—`
6. Инлайн-стили без единой сетки отступов/типографики
7. `attach_warnings` от backend игнорируются на фронте
8. Duplicate-кнопка есть в API, отсутствует на странице

## Что хотим поправить (MVP)

### Новая секция/вкладка **Logs**

Простой хронологический список событий кампании. Без новой инфраструктуры — собираем из того, что уже есть в БД:

- **Отправки/ошибки сообщений** — из `message_queue` (campaign_id, created_at/finished_at, error_message)
- **Lead / handoff / finish диалога** — из `llm_calls.tool_calls` (campaign_id, created_at) — надёжнее, чем статус диалога, не перезатирается

Это покрывает MVP: видно, что реально происходит с кампанией день за днём (кто написал, кому ответили, кто стал лидом, где ошибка).

**Не входит в MVP** (нет данных без новой таблицы — отдельная задача на будущее):
- История start/pause/resume/finish самой кампании
- История attach/detach senders
- Привязка restriction-событий конкретно к кампании (сейчас только к sender)

### Остальные правки (по приоритету)

1. Logs-секция (см. выше) — **топ приоритет**
2. Полная Funnel-карточка + визуализация воронки (эндпоинт `/analytics/funnel` уже есть, просто не используется)
3. Senders-панель с health/лимитами по каждому аккаунту
4. Превью вложений на самой странице
5. Явные loading/empty/error states
6. Показ `attach_warnings` при подключении sender
7. Duplicate-кнопка на странице
