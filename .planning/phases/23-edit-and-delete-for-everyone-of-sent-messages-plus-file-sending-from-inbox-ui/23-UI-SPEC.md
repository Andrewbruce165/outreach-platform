## ⚠️ Reconciliation notes (read first)

### 1. Copy is ENGLISH here — the inbox is an all-English screen (differs from RU screens)
Unlike `accounts.tsx`/`contacts.tsx` (which are Russian), the **deployed `inbox.tsx` is entirely English** ("Search conversations", "Take over", "Hand back to AI", "Send", "Thought trace", "No conversations", the delete AlertDialog copy). The Phase-23 error-code UI strings in `lovable-handoff/error-codes.md` are also English. **All new Phase 23 copy is English** to match the surface it lives on. Do NOT introduce Russian strings into the inbox. (This is the opposite of the Phase 20 accounts contract — intentional, because it is a different screen.)

### 2. "Delete" already means something else in this screen — the new action is "Delete for everyone" on a single MESSAGE
The existing inbox `Trash2` affordances (row hover + bulk bar + `AlertDialog`) delete a **conversation** from *your* inbox locally (`DELETE /conversations/{id}` / `POST /conversations/delete`). Phase 23 adds a **different** destructive action: delete a **single sent message** in Telegram **for both parties** (revoke). These must be visually and verbally distinct so a manager never confuses "remove this chat from my inbox" with "unsend this message in Telegram". The new action lives **on the message bubble**, is labelled **"Delete for everyone"**, and its confirmation explicitly says it is removed from the recipient's Telegram too. Leave the existing conversation-delete flow untouched.

### 3. Light theme only — no dark mode
Same as every prior phase: the app is **light-theme Telegram-blue** (`aimly.css`). The `.dark` scaffold in `src/styles.css` is dead. Do not introduce dark surfaces, oklch, or shadcn-default neutrals.

### 4. Align with the existing design system; do NOT invent tokens
All visual tokens come from the live `aimly.css` layer. The inbox is largely built with **inline `style={{…}}` referencing CSS variables** (e.g. `var(--tg-blue)`, `var(--danger)`, `var(--border)`) plus a few utility classes (`.btn`, `.btn--primary`, `.btn--ghost`, `.btn--sm`, `.input`, `.textarea`, `.scroll`, `.muted`, `.tb__icon-btn`). New markup reuses the **same variables and the same MessageBubble/composer structure** — it does not add a component library or new tokens.

### 5. The composer's Paperclip is already present but inert — Phase 23 wires it
`inbox.tsx` line ~1218 already renders a `Paperclip` icon-button (`aria-label="Attach file"`) with **no handler**. Phase 23 makes it the file-picker trigger for `POST /conversations/{id}/send-file` (D-09). Do not add a second attach control — wire the existing one. The `Smile` (emoji) button stays inert (out of scope).

### 6. Send-file inherits the composer's takeover gate; edit/delete do NOT
The composer is disabled while `conv.ai_enabled` is true (placeholder "Disable AI to send manually…"). **Send-file follows the same gate** — it is a new outbound and triggers auto-takeover server-side (D-12), so the attach button is disabled whenever the text composer is (AI enabled / sending / no conversation). **Edit and delete-for-everyone are past-edits with NO takeover** (D-04/D-08) and therefore are available on outbound bubbles **regardless of `ai_enabled`** — they are the one place manager actions are allowed while AI is still on.

### 7. `MessageBubble` must grow from text-only to typed bubbles
Today `MessageBubble` renders only `m.message_text`. Phase 23 extends it to render by `m.message_type` (`text | photo | video | voice | document`), an "(edited)" marker when `m.edited_at` is set, a download affordance for inbound file bubbles (D-16), and hover row-actions (edit ✏️ / delete 🗑) on **outbound** bubbles only (D-01/D-05). `message_text` is now `Optional` (file bubbles may have no caption).

## Phase 23 UI Surfaces

Five surfaces, all light-theme, all inside `src/routes/_authenticated/inbox.tsx` (+ small helpers). No new routes, no new pages.

**Visual hierarchy & focal point:** In the thread, the **message bubbles remain the focal column**; new controls are **secondary and progressively disclosed** — bubble row-actions (edit/delete) appear only on hover of an outbound bubble, and the download button sits inside inbound file bubbles. The composer's primary action stays the blue **Send** button; the attach control is a neutral icon-button beside it. Nothing new competes with the existing Take-over / Hand-back-to-AI header button for attention. Icon-only controls (attach, edit, delete, download, edit-cancel/save) all carry `aria-label`s.

### Surface 1 — Typed message bubbles (D-07/D-15/D-20)
`MessageBubble` renders by `m.message_type`:

| `message_type` | Rendering |
|----------------|-----------|
| `text` (default) | unchanged — `m.message_text` in the bubble |
| `photo` | thumbnail/preview area with `Image` placeholder icon + optional caption (`message_text`) below; inbound → lazy download/preview (Surface 4) |
| `video` | preview area with `Play` overlay + optional caption; inbound → lazy download |
| `voice` | `Mic` icon + "Voice message" label; if `message_text` carries the transcription (`[🎤 …]`) show it as muted secondary text below the label |
| `document` | file-row: `FileText` icon + `file_name` (fallback "File") + humanized `size_bytes` (e.g. "2.4 MB") + optional caption; inbound → **Download** button (Surface 4) |

- **Edited marker (D-07):** when `m.edited_at != null`, append a muted "(edited)" token next to the timestamp (both inbound and outbound). Do not show version history (none stored).
- **Outbound file bubbles** render the same file-row/preview, right-aligned, in the outbound bubble style; no download button (it's the manager's own upload).
- File-size formatting: bytes → `KB`/`MB` with one decimal; null size → omit.

### Surface 2 — Outbound bubble row-actions: Edit + Delete for everyone (D-01…D-08)
On **hover of an outbound bubble** (`direction='outbound'`), reveal a small action cluster (mirror the conversation-row hover-delete pattern at line 703 — absolutely-positioned, `--border` frame, `--bg` fill, subtle shadow):
1. **Edit** (`Pencil`, `aria-label="Edit message"`) — **only for `message_type='text'`** (D-05); hidden on file bubbles. Enters in-place edit mode (Surface 3).
2. **Delete for everyone** (`Trash2`, `aria-label="Delete for everyone"`, `--danger` color) — available on any outbound bubble (D-01). Opens the confirm dialog (Surface 5).

Actions appear regardless of `conv.ai_enabled` (Reconciliation §6). Inbound (contact) bubbles have **no** edit/delete affordances (D-01) — never render them.

### Surface 3 — In-place text edit (D-06/D-07/C1)
Clicking **Edit** swaps the bubble body for an inline editor:
- A `.textarea`-style editable field pre-filled with `m.message_text`, sized to the bubble, auto-focused, caret at end.
- Footer row: **Save** (`Check`, `btn--primary btn--sm`; pending "Saving…") + **Cancel** (`X`, `btn--ghost btn--sm`).
- Keyboard: `Enter` (or ⌘/Ctrl+Enter, matching composer) saves; `Esc` cancels.
- On save → `PATCH /conversations/{id}/messages/{message_id}` with body `{ message: <newText> }` (backend accepts `message`/`message_text`/`text` aliases, D-22).
- **Editing to identical text is a success no-op** (backend maps `MessageNotModifiedError` → 200; still stamps `edited_at`). Do not client-side-block "unchanged".
- Optimistic update: swap bubble text immediately, set a transient "(edited)" marker; on error, **roll back** to the prior text and toast (D-17).
- Empty text is not a valid edit (to clear content, use delete) — Save is disabled when the field is empty/whitespace.

### Surface 4 — Inbound file bubble: lazy download (D-16/C2)
For inbound `document`/`photo`/`video`/`voice` bubbles, render a **Download** affordance (`Download` icon + "Download"; for documents a full `btn--ghost btn--sm`, for media a small overlay button):
- Click → `GET /conversations/{id}/messages/{message_id}/download` (authenticated; returns raw bytes + `Content-Disposition`). Fetch as blob, trigger a browser save using `file_name`, then revoke the object URL. **Never** expose a public/raw blob URL and never base64-inline bytes into the messages list JSON (list carries only `file_name`/`mime_type`/`size_bytes`).
- While fetching: swap the button for a spinner + "Downloading…"; disable re-click.
- `MEDIA_UNAVAILABLE` (410) → the file is gone from Telegram: replace the button with muted "No longer available in Telegram" (do not toast repeatedly). `DOWNLOAD_FAILED` (502) → toast "Couldn't download the file. Try again." and keep the button.
- Optional image inline-preview is a nice-to-have (`?disposition=inline`); default behaviour is download-to-disk.

### Surface 5 — Delete-for-everyone confirm (D-02/D-03/C3)
Reuse the `AlertDialog` primitive (as at line 302), with copy that makes the two-sided revoke explicit (Reconciliation §2):
- Title: **"Delete this message for everyone?"**
- Body: **"This message will be permanently removed from your chat and from {contact_name}'s Telegram. This can't be undone."** (fall back to "the recipient's Telegram" when no name).
- Actions: **Delete for everyone** (`--danger` background, white text) + **Cancel** (`AlertDialogCancel`).
- On confirm → `DELETE /conversations/{id}/messages/{message_id}`. Success → toast "Message deleted", **remove the bubble** (backend hard-deletes the row; the conversation `last_message` preview auto-recomputes), invalidate `["messages", id]` + `["conversations"]`. No takeover, no status change (D-04).
- `DELETE_FAILED` (502) → toast "Couldn't delete the message. Try again."; keep the bubble (optimistic removal must roll back on error).

### Surface 6 — Send file from composer (D-09…D-14/C4)
Wire the existing inert `Paperclip` button (Reconciliation §5):
- Click → open a hidden `<input type="file">` (no `accept` restriction — **any type**, D-10). On pick, show a **staged-attachment chip** above the textarea: file icon + name + humanized size + a `X` remove button. The textarea caption becomes the file's caption (optional).
- **Client-side size pre-check:** reject > 50 MB before upload → inline composer error "File is larger than 50 MB." (mirrors server `FILE_TOO_LARGE` 413). Nothing is sent.
- Submit (Send button, or a dedicated "Send file" state of it) → `POST /conversations/{id}/send-file` as `multipart/form-data`: the file part + a `message`/`caption` text part (alias-tolerant, D-22). Show progress: Send disabled + "Uploading…".
- On success → clear the staged chip + caption, append the new outbound file bubble, invalidate `["messages", id]` + `["conversations"]`. Because this is a new outbound, the server auto-takes-over (`status='manual'`, `ai_enabled=false`) — the UI should reflect the flipped state on refetch (the header switches to "Hand back to AI", composer stays enabled).
- **Gate:** the attach button is disabled whenever the text composer is (no conversation / `conv.ai_enabled` / in-flight). Photos/videos arrive inline; other types as documents (server-side auto-media, D-11) — the UI does not choose.
- Caption > 1024 chars is allowed (server sends overflow as a follow-up text message, D-13) — do not client-block long captions.

## Interaction Contracts

### C1 — Edit ordering & error mapping (D-06/D-07/D-17)
Optimistic swap of bubble text on Save; the network call is `PATCH …/messages/{message_id}`. Roll back to prior text on any error and toast the mapped string. Error codes (from `error-codes.md`): `MESSAGE_EDIT_TOO_OLD` (409) → "This message is too old to edit."; `MESSAGE_NOT_EDITABLE` (422) → "This message can't be edited."; `MESSAGE_NOT_FOUND` (404) → "Message not found"; unmapped Telethon → `TELEGRAM_OP_FAILED` (502) "Telegram operation failed. Try again.". `MessageNotModified` never surfaces as an error (server returns success).

### C2 — Lazy download (D-16)
`GET …/messages/{message_id}/download` → blob → save-as `file_name`. Per-bubble download state (idle / downloading / unavailable). `MEDIA_UNAVAILABLE` (410) is terminal per bubble (show muted unavailable label); `DOWNLOAD_FAILED` (502) is retryable (toast + keep button).

### C3 — Delete-for-everyone ordering (D-02/D-03/D-04)
Confirm → optimistic bubble removal → `DELETE …/messages/{message_id}`. On success keep it removed (row hard-deleted server-side). On `DELETE_FAILED` restore the bubble + toast. **No** conversation status / `ai_enabled` / queue mutation is expected or shown (D-04). The action is available even when AI is enabled.

### C4 — Send-file flow (D-09…D-14)
Pick → stage chip (with 50 MB client pre-check) → optional caption → submit multipart → "Uploading…" → success appends bubble + reflects auto-takeover on refetch. Reused error codes apply: `NO_TELEGRAM_ID` (400) "This contact has no Telegram account on file."; `RECIPIENT_NOT_IN_TELEGRAM` (422); `FLOOD_WAIT` (429, carries `retry_after`) "Sending too fast. Try again in {retry_after}s."; `ACCOUNT_FROZEN` (409); `USER_IS_BLOCKED` (409) "The recipient has blocked this account."; `FILE_TOO_LARGE` (413) "File is larger than 50 MB.". Send-file errors render as the **inline composer banner** (like the existing `sendError`), not a toast, so the staged file stays for retry.

### C5 — Optimistic-UI + rollback discipline (D-17, applies to all four ops)
Every mutation optimistically updates the thread, then reconciles on response. On any structured error: **roll back the optimistic change** and surface the mapped UI string (Sonner toast for edit/delete/download; inline banner for send-file). Never display the raw backend `message` — always map `detail.code` → the friendly English string in `error-codes.md`.

## Typography

Inherited from `aimly.css` + the inbox's established inline sizes. **Exactly 4 distinct font sizes and exactly 2 font weights** are in the contract: **regular 400** and **semibold 600**. Roles are differentiated by SIZE + COLOR (muted) + CASE — never a third weight.

| Role | Size | Weight | Line Height | Differentiation |
|------|------|--------|-------------|-----------------|
| Label (uppercase micro-labels: trace section labels, "(edited)" marker, staged-chip meta, timestamps) | 10–11px | 600 (uppercase labels) / 400 (timestamps, muted) | 1.3 | uppercase micro-labels add letter-spacing `0.04em`; timestamps/"(edited)"/download-size are 11px muted regular. Distinguished by case + color, not a new weight. |
| Body | 13.5px | 400 | 1.5 | message bubble text, composer textarea, file names, captions — the base content tier (bubbles render at 13.5/1.5 today) |
| Heading (thread header labels, pane titles, dialog title) | 13–14px | 600 | 1.2 | the header/title tier; distinguished from Body by size + weight |
| Display | 24px | 600 | 1.1 | (not introduced by this phase; reserved for analytics metric values elsewhere) |

**Weight reconciliation (2-weight rule):** the contract declares **only 400 and 600**. Where the inherited inbox renders certain labels/nav at the intermediate **500** (e.g. contact name `fontWeight:500`, filter chips), that is a **component-intrinsic value owned by the shared design system** — it is not a weight this phase introduces. All **new Phase 23 markup uses 400 or 600 only.** Numeric/size values may use `tabular-nums` where alignment matters.
