<objective>
Build the FollowUpWorker — the timer-driven state machine that ties Phase 19 together. Each tick sweeps eligible conversations of running follow-up-enabled campaigns, applies the auto-finish-first / ping-else rule anchored to the last outbound message, generates ping text via generate_followup_ping (Plan 19-02), enqueues it as a follow-up item to the owning sender (Plan 19-03 guards it), and fires the finish webhook with reason='no_reply' on auto-finish. Register it in the lifespan with a config knob, and add the no_reply reason marker to webhook_notify.

Purpose: This is the orchestrator that consumes the contracts from 19-01/02/03. It is the only plan touching follow_up.py + config.py + main.py + webhook_notify.py.
Output: FollowUpWorker service, config knob, lifespan registration, webhook reason marker.
</objective>

  <behavior>
    - Interval elapsed on an `active` conversation → flip to `no_reply`, generate + enqueue a ping, increment pings_sent (NORP-04, D-02).
    - `no_reply` conversation whose interval elapses again and pings_sent < max → another ping, pings_sent++.
    - auto_finish_hours elapsed since last outbound OR pings_sent >= follow_up_max_pings → conversation flips `finished`, pending pings cancelled, finish webhook fires reason='no_reply' (auto-finish takes precedence — D-08).
    - Conversations in lead/handoff/manual/paused/finished are never touched (D-06).
    - Campaigns not (status='running' AND follow_up_enabled=true) are not evaluated (D-16).
    - Owning sender restricted → skip the ping enqueue this tick (retry next tick), but auto-finish still closes on time (D-14).
    - On enable of an already-running campaign, a dialog already past auto_finish_hours is finished immediately without a ping (D-15).
  </behavior>
  <action>
    Create app/services/follow_up.py with a `FollowUpWorker` class copied structurally from CampaignEnqueueWorker (async task, start/stop/_run/_tick, broad-except-never-die, poll_interval = settings.follow_up_tick_seconds). Export a module-level singleton `follow_up_worker = FollowUpWorker()`.

    `_tick()` (one AsyncSessionLocal session):
    1. SELECT eligible conversations JOINed to campaigns:
         SELECT c.id, c.status, c.pings_sent, c.workspace_id, c.sender_id, c.contact_phone, c.contact_name,
                c.campaign_id, cp.follow_up_interval_hours, cp.follow_up_max_pings, cp.auto_finish_hours
         FROM conversations c
         JOIN campaigns cp ON cp.id = c.campaign_id
         WHERE cp.status = 'running' AND cp.follow_up_enabled = true
           AND c.status IN ('active','no_reply')
         FOR UPDATE OF c SKIP LOCKED
         LIMIT <a sane batch, e.g. 200>
    2. For each conversation compute last_outbound_at = MAX(messages.created_at WHERE conversation_id=c.id AND direction='outbound'). (Derive lazily per RESEARCH Pattern 2 recommendation — no stored column.) If NULL (no outbound yet) skip.
    3. AUTO-FINISH FIRST (D-08): if NOW()-last_outbound_at >= auto_finish_hours*interval OR pings_sent >= follow_up_max_pings:
         - UPDATE conversations SET status='finished', updated_at=NOW() WHERE id=c.id
         - cancel pending ping queue rows for this conversation (UPDATE message_queue ... status='cancelled' ... WHERE campaign_id=:cid AND recipient_phone=:phone AND sender_id=:sid AND status='pending')
         - fire the finish webhook: load the campaign dict (id/name/workspace_id/finish_webhook_url/webhook_url) + contact dict, call `await webhook_notify.notify_signal(event_type='finish', campaign=..., conversation_id=c.id, contact=..., reason='no_reply', db=session)`
         - continue (do NOT also ping)
    4. PING (else) (D-02/D-04): if NOW()-last_outbound_at >= follow_up_interval_hours AND pings_sent < follow_up_max_pings:
         - D-14: check the owning sender's restriction_status; if != 'none' → skip this conversation (retry next tick), continue.
         - Guard double-enqueue: if a pending ping row already exists for this conversation → skip.
         - If status=='active' flip to 'no_reply' (D-02 — only from active; no_reply stays).
         - ping_text = await ai_engine.generate_followup_ping(session, c.id); if None → skip (log).
         - await enqueue_message(session, workspace_id=c.workspace_id, sender_id=c.sender_id, sender_slug=<resolve>, recipient_phone=c.contact_phone, recipient_name=c.contact_name, message_text=ping_text, metadata={"kind":"followup"}, campaign_id=c.campaign_id)
         - UPDATE conversations SET pings_sent = pings_sent + 1 WHERE id=c.id
       (last_outbound_at advances naturally when the ping actually sends and writes an outbound messages row — do not fake it here.)
    5. Use timezone-aware datetime (datetime.now(timezone.utc)); do N'T call time.sleep; async everywhere.
    Note the D-16 pause semantics use wall-clock (no pause-duration compensation for v1 — RESEARCH Open Question 1); add a one-line comment flagging this simplification.
