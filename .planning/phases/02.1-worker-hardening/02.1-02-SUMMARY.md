# Phase 02.1 Plan 02: Reauth Flow + Migration 014 Summary

**One-liner:** Закрыты CR-05 (reauth IntegrityError) и WR-02 (slug globally UNIQUE) — `senders.slug` теперь per-workspace UNIQUE, reauth flow UPDATE'ит существующий sender через `_refresh_sender_session` вместо INSERT.

## Accomplishments

- **CR-05 (reauth IntegrityError):** Reauth для существующего sender'а через `/reauth/{sender_slug}` больше не падает с IntegrityError. Flow:
  1. `reauth_start` / `reauth_qr` сохраняют `original_sender_id` в onboarding_sessions
  2. `verify_code` / `verify_2fa` / QR-callback вызывают единый `_finalize_onboarding_or_reauth`
  3. Helper проверяет: если original_sender_id NOT NULL И sender существует в workspace → `_refresh_sender_session` (UPDATE session_string + auth_status='ok'); иначе → `_create_sender_from_session` (INSERT)
  4. Cross-workspace original_sender_id → fallback на create (защита от leak'а)
- **WR-02 (slug globally UNIQUE):** Миграция 014 дропает global constraint, создаёт `UNIQUE (workspace_id, slug)` индекс. Два workspace'а могут иметь sender с одним и тем же slug.
- **OnboardingSession.original_sender_id:** Новая nullable колонка с FK на senders(id) ON DELETE SET NULL — маркер reauth vs нормального онбординга.
