# Phase 15 — UI Design Contract

> Visual and interaction contract for the **Warmup / Прогрев** tab. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Brownfield note.** The frontend is a mature, already-built app (sibling repo `/root/apps/aimly/aimly-tg-outreach`, TanStack Start + React + TS, generated via Lovable). It runs a **custom CSS-token design system** ("Pulse", Telegram-blue light theme, defined in `src/styles/aimly.css`) layered on top of shadcn (new-york) primitives. **This phase adds ONE new tab. It MUST reuse the existing tokens, classes and component patterns verbatim — it does not introduce a new visual language.** Everything below is extracted from the live frontend, not invented. Where this contract says "use X", X already exists in `aimly.css` / `src/components`.
>
> All UI copy is **Russian** (the app's UI language; existing nav labels are English-ish — "Dashboard", "Campaigns" — but body/empty/error/warning copy mixes; this tab follows the user's stated preference: Russian for all user-facing copy on this tab). Source for every interaction decision: `15-CONTEXT.md` D-01..D-14.

## Spacing Scale

The live system is on an effective 4px grid but with a few established non-grid values (`14px` card padding, `18px` card body, `7px` small-button radius). **Reuse the existing values — do not "correct" them to a pure 8-point scale.** Declared (multiples of 4 where the system uses them):

| Token | Value | Usage (as used in the live app) |
|-------|-------|---------|
| xs | 4px | Icon-to-label micro gaps, badge inner padding |
| sm | 8px | Compact element spacing, mini-metric grid is `gap: 12` (see exception) |
| md | 16px | Card header padding (`16px 18px`), section bottom margins (`marginBottom: 16`) |
| lg | 24px | Page body padding (`.scroll { padding: 24 }` — matches `accounts.tsx`) |
| xl | 32px | Major vertical section breaks within the tab |
| 2xl | 48px | Empty-state vertical centering block |
| 3xl | 64px | Reserved — not expected on this tab |

Exceptions (all pre-existing in `aimly.css`, reuse verbatim, do NOT invent new ones):
- Mini-metric grid gap `12px`, card body padding `18px`, card header `16px 18px`.
- Button heights `36px` (default) / `30px` (`--sm`); sidebar item height `36px`.
- Border radii from `--r-*`: `6 / 10 / 14 / 20 / 999`; button radius `9px` (default) / `7px` (`--sm`).

## Typography

Base is `14px / line-height 1.45` on `body` (set in `aimly.css`). The 4 roles below are the only ones used on this tab; weights are limited to **2** (400 regular, 600 semibold) — `500` appears on `.btn`/active nav but treat 600 as the heading weight and 400 as body for the checker's 2-weight rule; **500 is the single permitted intermediate already baked into `.btn`/`.sb__item.is-active` — reuse those classes, do not add new 500 usages.**

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px | 400 | 1.45 |
| Label / meta | 12px | 500 (in `.metric__head`/`.card__sub` — pre-existing) | 1.3 |
| Heading (card/section title) | 14px | 600 | 1.3 (`.card__title`) |
| Display (page/Topbar title, big metric value) | 17–20px | 600 | 1.2 |

Notes: section eyebrow labels use the pre-existing `.sb__section` pattern (11px, uppercase, `letter-spacing 0.06em`, weight 600, `--text-faint`). Numeric metric values use `--mono` is **not** required — the live `MiniMetric` uses the body font; match it.

## Color

Light theme only (no dark mode on this tab). The 60/30/10 split maps onto the existing `aimly.css` surfaces:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `--bg-soft` `#f4f5f7` (page) / `--surface` `#ffffff` (cards) | Page background + card/table surfaces |
| Secondary (30%) | `--bg` `#ffffff` sidebar, `--surface-2` `#f7f8fa`, `--border` `#ebedf0` | Sidebar, dividers, table header rows, hover fills |
| Accent (10%) | `--tg-blue` `#3390ec` (+ `--tg-blue-soft` `#e8f3fe` fill) | See reserved-for list below |
| AI accent | `--ai-purple` `#8774e1` (+ `--ai-purple-soft`) | Warmup = AI-driven: optional accent for the "AI chats" framing / level shimmer ONLY |
| Status: success | `--success` `#4dcd5e` / `--success-soft` | Account actively warming, "прогрев включён" |
| Status: warning | `--warning` `#f5a623` / `--warning-soft` | Soft caution (e.g. account in level transition, near daily cap) |
| Destructive / danger | `--danger` `#e13b30` / `--danger-soft` | Restriction-blocked accounts, stop-warmup destructive confirm |

**Accent (`--tg-blue`) reserved for — explicit list (never "all interactive elements"):**
1. The single primary CTA on the tab (master "Включить прогрев" button — `.btn--primary`).
2. Active nav state of the new `Прогрев` sidebar item (`.sb__item.is-active` — blue text + `--tg-blue-soft` fill, pre-existing).
3. The master warmup toggle in its ON state (shadcn `Switch` checked = primary).
4. Primary numeric emphasis on the "пул греется" mini-metric value.

`--ai-purple` is reserved ONLY for signalling that warmup chat content is AI-generated (e.g. a small "AI" chip on a session row, or the level-progress accent). It is NOT a second general accent — do not use it on buttons or nav.

**Restriction visibility (D-11/D-14) color rule:** an account that cannot warm up because of `restriction_status != 'none'` or a future `restricted_until` MUST render its status with `--danger`/`--danger-soft` (or `--warning` for soft `spam_limited`) plus a textual reason — never silently grey. This is the user's explicit "видно, ПОЧЕМУ аккаунт не греется" requirement.

| Destructive confirmation — remove account from pool | Title `Убрать аккаунт из прогрева?` · Body `Аккаунт перестанет переписываться с другими. Его историю прогрева это не удалит.` · Confirm `Убрать` (`--danger`) · Cancel `Отмена` |

**Destructive actions in this phase (each needs the confirm pattern above):**
1. Master "Выключить прогрев" (workspace-wide stop) — use shadcn `AlertDialog`.
2. "Убрать аккаунт из прогрева" (`DELETE /pool/{sender_id}`) — use shadcn `AlertDialog`.
(Per-account "пауза" via `PATCH /pool/{id}/toggle` is reversible — no confirm dialog, just an inline toggle + toast.)
