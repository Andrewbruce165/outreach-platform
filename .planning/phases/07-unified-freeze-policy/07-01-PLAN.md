<objective>
Converge the antispam-signal code path onto the already-working PEER_FLOOD soft-restriction pattern, so a real antispam warning PAUSES the sender (auto-resumable by the existing reconcile sweep) instead of terminally KILLING the queue, and stops silencing AI in established dialogues. Purpose: The b7cc7d06 incident terminally `failed` 37 contacts on a single antispam signal with no auto-resume, and silenced every dialogue on that account. Telegram does NOT block replies in established conversations during a soft spam-limit, so silencing them is needless lost engagement. PEER_FLOOD already handles this correctly — this phase makes the antispam path identical.

Output: rewritten `_handle_antispam_signal`, a one-line rotation filter, an updated cancel-path test, and a new rotation regression test. NO migration (028 already shipped `restriction_status` / `restricted_until`).

<threat_model>
Threat surface is internal state-machine abuse, not external input (no new endpoints, no untrusted parsing in this phase).

1. **State-machine abuse — restricted sender re-armed for cold outreach.**
   - Risk: a `spam_limited` sender keeps `lifecycle_status='active'` + `auth_status='ok'` by design (migration 028), so the rotation candidate query currently still hands it new cold contacts, deepening the limit.
   - Mitigation: Task 2 adds `AND s.restriction_status = 'none'` to the rotation candidate WHERE clause (FRZ-04). Verify no other cold-assignment path bypasses it: the only cold-contact assignment is `rotation.get_or_assign_sender`; the pre-send worker already skips restricted senders (queue.py:401). No bypass remains.

2. **Reconcile loop / clear→reflag oscillation.**
   - Risk: the reconcile sweep pings @SpamBot itself; that solicited reply lands in the listener stream and, if processed as a real warning, would re-flag the sender we are trying to clear — an infinite spam_limited loop.
   - Mitigation: Task 1 PRESERVES the `is_spambot_selfcheck(sender_slug)` early-return as the FIRST statement of `_handle_antispam_signal` (listener.py:901-905). The reconcile passes `selfcheck_key=slug` to arm this window. Test `test_antispam_guard_skips_when_selfcheck_active` asserts the guard short-circuits. Documented limitation (out of scope): the in-memory registry covers the listener process (reconcile sweep) but NOT the manual `/spambot-check` API endpoint in the api process — unchanged from 260622-gxt.

3. **frozen-vs-spam_limited precedence (silent downgrade).**
   - Risk: a soft antispam signal writing `restriction_status='spam_limited'` over a sender already `frozen` (hard restriction) would downgrade severity.
   - Mitigation (DECISION, recommended default): Task 1 guards the senders UPDATE with `AND restriction_status <> 'frozen'`, matching frozen-precedence intent. Benign either way (frozen accounts are not sending), but explicit guard removes the race.

**No HIGH threats remain after mitigation.** No external input, no auth surface, no new migration. ASVS L1: not applicable beyond internal invariants above, which are covered.
</threat_model>
