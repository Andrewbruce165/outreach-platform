# Phase 05.1 — UI Design Contract (Lovable v1 / aimly)

> **Visual source of truth:** `./design-source/` — Claude Design handoff bundle. CSS tokens, screen JSX, and prototype mockups already specify pixel-level decisions. This spec locks the **contract** (semantics, screen behaviors, API mappings, copy, accessibility, registry) — not pixels.
> Lovable should ingest `design-source/project/styles.css` verbatim, then build each screen against the JSX reference in `design-source/project/screens/*.jsx`, and wire to the FastAPI endpoints documented in §5.
> Backend phases 1–5 are released. Frontend ships separately on Lovable using Supabase magic-link auth → JWT bearer to `/api/v1/*`.

## 0. Goal Recap

| Aspect | Value |
|--------|-------|
| Phase goal | Ship a Lovable-built front that lets a client run the full v1 flow unaided: auth → onboarding → TG account → contacts → agent → campaign → inbox → analytics → settings |
| Core Value test | `time_to_first_campaign_seconds < 600` (10-minute path from signup to launched campaign) — measured by telemetry §9 |
| HUMAN-UAT coverage | All 7 items from `.planning/phases/05-inbox-analytics/05-HUMAN-UAT.md` exercisable through the UI (auto-takeover, bot filter, analytics, LLM log, etc.) |
| Frontend stack | Lovable (React 18 + Vite + Tailwind + shadcn/ui + TanStack Query + react-hook-form + zod) |
| Auth | Supabase Auth (magic link, SDK-embedded) → JWT in `Authorization: Bearer` to backend |
| Language | English (en-US) for UI chrome; user-generated content (contact names, message templates, agent prompts) renders in any language untouched |
| Brand | **aimly** (lowercase, no exclamation marks, AI-first SaaS tone) |
| Out of scope | Push notifications, mobile-native app, real-time websocket inbox (10s poll suffices), HMAC webhook signing, multi-user workspaces (v2) |

**Weight contract — exactly 2 weights for UI text:**
- **400 regular** — body, body-muted, metadata
- **600 semibold** — titles, metric values, brand, active nav, table column headers when emphasized

**Documented deviation:** `design-source/project/styles.css` uses weight `500` in several selectors (`.sb__brand-plan` 11/500, `.btn` 13/500, `.metric__head` 12/500, `.field__label` 12/500, `.sb__item.is-active` 14/500). To honor the GSD typography contract (max 2 weights), **Lovable should remap weight-500 usages to weight 400 + reduce size by 1–2px + apply a muted color** to preserve hierarchy without an additional weight tier. Example: `.field__label` becomes 12/400/`--text-soft` instead of 12/500/`--text-soft`. The visual difference is negligible at 12–14px; the contract benefit is one less weight to load and a cleaner mental model. If Lovable disagrees after a side-by-side comparison, weight 500 may be added — this deviation must then be re-documented.

### 1.7 Motion (from styles.css lines 459–495)

Two AI-motion primitives are pre-defined and **reserved for AI moments only**:

| Keyframe | Defined at | Use |
|----------|-----------|-----|
| `pulse-ring` | line 471 | `.live-dot` — animated halo around live indicator (dashboard "Conversion funnel" updating-live chip, running campaign topbar) |
| `shimmer` | line 477 | `.ai-shimmer` — left-to-right gradient sweep for generation/loading state (AI suggestion placeholder, generation skeleton) |

Standard motion (button hovers, modal fade, toggle slide) uses CSS `transition: ...` already defined per-element (e.g. `.btn` line 296: `transition: all 0.12s`). The launch overlay uses a JS-driven sequential stage swap (no keyframe). Lovable should not introduce additional motion libraries (Framer Motion etc.) — the CSS-only motion in the source is the contract.

**Bar/funnel charts are CSS-flex, not SVG `preserveAspectRatio="none"`.** The Sankey funnel on the Dashboard is the one SVG chart in the design (used because it requires curved ribbons). All other bar charts (`<BarChart>` in accounts.jsx 24h volume, FunnelMini, corridor bars) are pure CSS flex/grid with percentage widths — no SVG scaling tricks. This avoids the historical `preserveAspectRatio` blur/distortion bug and keeps the layout responsive without JS measurement.

**Reduced motion:** Lovable must wrap motion in `@media (prefers-reduced-motion: reduce) { .live-dot, .ai-shimmer { animation: none; } }` — the source CSS does not include this guard, and it's a hard a11y requirement.

## 6. Interaction Patterns

### 6.1 Forms

- **Validation:** zod schemas + react-hook-form via `@hookform/resolvers/zod`. Trigger on `onBlur` per-field, `onSubmit` for cross-field.
- **Input height:** 38px (from `styles.css` line 522). Focus ring: `box-shadow: 0 0 0 3px rgba(51, 144, 236, 0.12)` + `border-color: var(--tg-blue)`.
- **Error display:** inline below field, `--danger` color, 11.5px, weight 400, role="alert" + `aria-describedby` link.
- **Submit feedback:** button disabled + inline `<Spinner>` + text changes ("Sending…", "Saving…"). On success → Sonner toast + optional redirect.
- **Required marker:** asterisk * in `--danger` after label text.

### 6.2 Wizards (Onboarding, Campaign builder, CSV import)

- Top steps rail (left) or stepper (horizontal) — current step `--tg-blue-soft` bg, completed = green check chip.
- Sticky bottom bar with **Back** (`--ghost`, disabled on step 1) and **Continue** (`--primary`) or **Launch** (`--dark` on terminal step).
- `⌘+Enter` advances to next step from any focused field.
- Quit: top-right close (X) → AlertDialog "Discard {{N}} steps? Your progress isn't saved." — except builder where "Save as draft" is offered.

### 6.3 Toasts (Sonner)

| Variant | Background | Auto-dismiss | Position |
|---------|-----------|--------------|----------|
| success | `--success-soft` bg + `#1e8a3a` text | 4s | top-right |
| info | `--bg` + `--border` | 5s | top-right |
| warning | `--warning-soft` + `#a86200` | 6s | top-right |
| error | `--danger-soft` + `#b8332a` + Action button "Retry" | 8s | top-right |

Max 3 visible, newest on top. All toasts respect `prefers-reduced-motion` (no slide).

### 6.4 Loading (4-tier policy)

1. **Initial page load** → `<Skeleton>` matching exact layout shape.
2. **In-flight mutation** → button disabled + inline spinner; list/table overlay 60% opacity + centered spinner.
3. **Background refetch** (poll) → NO indicator (avoid flicker).
4. **Long-running async** (CSV import, onboarding QR poll, launch overlay) → `<Progress>` bar or sequential-stage overlay (per design's `LaunchOverlay` / `ImportOverlay` patterns).

### 6.5 Empty states (4-element formula)

Every empty state must have all four:

1. **Icon** (lucide-react, 96×96px, `--text-faint` color)
2. **Heading** (16/600, no trailing period)
3. **Body** (1–2 sentences, what + why)
4. **CTA** (primary button) — or text hint if no action is possible

### 6.6 Error boundaries

- React `<ErrorBoundary>` at AppShell level → fallback page "Something went wrong" + Reload button.
- API errors → TanStack Query global `onError` → Sonner toast with `code: message`.
- **401** → auto-redirect to `/login` + toast "Your session expired. Sign in again."
- **403** → `/forbidden` page or inline Alert.
- **404** → "Not found" page + "Back to dashboard" CTA.
- **5xx** → toast destructive "Server is unreachable. Retry." + Retry action.

### 6.7 Destructive confirmations (3-tier)

1. **Low risk** (revoke key, delete unused agent, dismiss banner) → AlertDialog with 2 buttons.
2. **Medium risk** (delete sender / folder / campaign in draft) → AlertDialog + mandatory checkbox "I understand the consequences".
3. **High risk** (delete running campaign / sender with active campaign / cascade-delete folder with contacts) → custom `<ConfirmDestructiveDialog>` with **type-the-name** pattern (user must type the exact name to enable the destructive button).

### 6.8 Keyboard shortcuts

| Shortcut | Action |
|----------|--------|
| `⌘K` / `Ctrl+K` | Open command palette (v2; v1 stub disabled with tooltip "Coming soon") |
| `Esc` | Close modal / sheet / popover |

## 8. Localization & Tone

### 8.1 Language

- **UI chrome:** English (en-US) per `design-source/chats/chat1.md` decision.
- **User-generated content** (contact names, agent prompts, message templates, FAQ, Telegram bot responses) renders in whatever language the user wrote — Russian, English, Spanish, etc. The UI does not translate or modify.
- **No i18n library required for v1.** Strings are inline in components. If multi-locale is needed in v2, prepare by routing strings through a `t('key')` helper from day 1 (Lovable convention; non-blocking).
- **Backend errors:** arrive as `{ code: 'SENDER_LOCK_CONFLICT', message: '...' }`. Frontend maps `code` → user-friendly English string via a lookup map. Never display raw backend `message` (often English internal-speak).

### 8.2 Tone

- **AI-first SaaS voice:** concise, action-oriented, lowercase product name (`aimly`).
- **No exclamation marks anywhere in UI.** No emoji. No marketing fluff.
- **Active voice:** "Connect account" not "Account can be connected".
- **CTA pattern: verb + noun.** "Send magic link" / "Add account" / "Import CSV" / "Create campaign" / "Launch campaign" / "Pause campaign" / "Hide LLM trace" / "Take over".
- **Examples:**
  - ✓ "Launch your first campaign"
  - ✗ "Ready to launch? Let's go!"
  - ✓ "Couldn't send the link. Try again."
  - ✗ "Oops! Something broke :("
