# Phase 05.1 — UI Design Contract (Lovable v1)

> Контракт для построения Lovable-фронта v1: auth → onboarding → TG accounts → contacts → agents → campaigns → inbox → analytics → settings.
> Цель — закрыть Core Value ("10 минут от регистрации до запущенной кампании") и 7 HUMAN-UAT items из Phase 5 VERIFICATION.
> Backend (Phases 1-5) уже зарелизен; фронт идёт в отдельном Lovable-репо, использует Supabase JWT + bearer-auth к FastAPI `/api/v1/*`.
> Спека намеренно лаконична — Lovable допишет low-level Tailwind; контракт фиксирует решения, не пиксели.

## 0. Goal Recap

| Aspect | Value |
|--------|-------|
| Phase goal | Клиент проходит весь v1-флоу через UI, без программистов |
| Core Value test | За 10 минут: регистрация → подключенный TG → кампания запущена |
| HUMAN-UAT coverage | 7 items из `.planning/phases/05-inbox-analytics/05-HUMAN-UAT.md` (auto-takeover, bot filter, analytics, LLM log) |
| Frontend stack | Lovable (React 18, Vite, shadcn/ui, Tailwind v3, TanStack Query, react-hook-form + zod) |
| Auth | Supabase Auth (magic link, embedded SDK) → JWT в `Authorization: Bearer` к backend |
| Language | Все user-facing строки — русский (B2B-формальный «вы») |
| Out of scope | Push-notifications, mobile-app, real-time websocket inbox (poll каждые 10s достаточно), HMAC webhook |

## 1. Design Tokens

### 1.1 Design System

| Property | Value |
|----------|-------|
| Tool | shadcn/ui (Lovable-native) |
| Preset | new-york style, neutral base, CSS variables, Tailwind v3 |
| Component library | shadcn (Radix primitives под капотом) |
| Icon library | `lucide-react` (default для shadcn, 1.5px stroke) |
| Font | `Inter` variable (latin + latin-ext + cyrillic subsets обязательно), system fallback `-apple-system, "Segoe UI", "Helvetica Neue"` |
| Mono font | `JetBrains Mono` для API-ключей, webhook URL, JSON payload, кода |

### 1.2 Spacing Scale (8-point grid)

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding |
| sm | 8px | Compact element spacing, form-field internal |
| md | 16px | Default element spacing, card internal padding |
| lg | 24px | Section padding, card-to-card gap |
| xl | 32px | Layout column gaps |
| 2xl | 48px | Major section breaks (empty-state hero, dashboard hero) |
| 3xl | 64px | Page-level spacing (top padding of wizard hero only) |

Exceptions:
- **44px** минимальная touch-target высота для primary buttons (a11y; не на сетке но соответствует Material/iOS guidelines)
- **20px** для inbox message-bubble padding (вынужденное между sm/md из chat-UX traditions — единственное исключение, иконфирмируется в `globals.css`)

### 1.3 Typography

| Role | Size | Weight | Line Height | Use |
|------|------|--------|-------------|-----|
| Display | 28px | 600 semibold | 1.2 (33.6px) | Page heroes (Dashboard, Onboarding step titles) |
| Heading | 20px | 600 semibold | 1.3 (26px) | Section/card titles, dialog titles |
| Body | 16px | 400 regular | 1.5 (24px) | Default text, paragraphs, table cells |
| Label | 14px | 500 medium | 1.4 (19.6px) | Form labels, table headers, breadcrumbs, badges |

**Размеры строго 4 ступени, веса строго 3 (400/500/600).** Кодовые сниппеты — `JetBrains Mono 13px / 1.5`.

### 1.4 Color (60/30/10 + destructive + success)

| Role | Light | Dark | Usage |
|------|-------|------|-------|
| Dominant (60%) | `hsl(0 0% 100%)` (#FFFFFF) | `hsl(240 10% 4%)` (#0a0a0b) | Page background, main surface |
| Secondary (30%) | `hsl(240 5% 96%)` (#f4f4f5) | `hsl(240 4% 11%)` (#1c1c1f) | Sidebar, cards, table headers, popover |
| Accent (10%) | `hsl(221 83% 53%)` (#2563eb, Tailwind blue-600) | `hsl(217 91% 60%)` (#3b82f6, blue-500) | Primary CTA, active nav item, link, focus ring |
| Destructive | `hsl(0 72% 51%)` (#dc2626, red-600) | `hsl(0 63% 50%)` (#ef4444, red-500) | Только destructive actions (Удалить, Остановить кампанию, Отозвать ключ) |
| Success | `hsl(142 71% 45%)` (#16a34a, green-600) | `hsl(142 76% 50%)` (#22c55e, green-500) | Status badges «активен», «зарегистрирован», success toast |
| Warning | `hsl(38 92% 50%)` (#f59e0b, amber-500) | same | Status «прогрев», «вне зелёного коридора», soft-warning toast |
| Muted text | `hsl(240 4% 46%)` | `hsl(240 5% 65%)` | Hints, placeholders, timestamps, secondary labels |

**Accent reserved-for list (НЕ "all interactive"):**
1. Primary CTA buttons (одна на экран максимум: «Запустить кампанию», «Подключить аккаунт», «Сохранить»)
2. Active item в sidebar nav
3. Inline link и breadcrumb current segment
4. Focus ring (2px outline)
5. Checkbox/radio/switch checked state
6. Loader spinner stroke

Secondary buttons — `border + muted-foreground`, не accent. Tabs — underline-only без accent fill. Selected row — `bg-secondary` без accent.

**Dark theme:** автоматически через `prefers-color-scheme` + manual toggle в shell header. Default = system. Все compoнения через CSS-variables, не hardcoded HEX в JSX.

### 1.5 Radius, Shadow, Border

| Token | Value | Use |
|-------|-------|-----|
| radius-sm | 4px | Badges, inline tags |
| radius-md | 6px | Inputs, buttons, table rows |
| radius-lg | 8px | Cards, dialogs, popovers |
| radius-full | 9999px | Avatars, status dots |
| shadow-sm | `0 1px 2px 0 rgb(0 0 0 / 0.05)` | Sticky header, kbd |
| shadow-md | `0 4px 6px -1px rgb(0 0 0 / 0.1)` | Cards on hover, dropdown |
| shadow-lg | `0 10px 15px -3px rgb(0 0 0 / 0.1)` | Dialog, command-palette |
| border | 1px solid `hsl(240 6% 90%)` (light) / `hsl(240 4% 16%)` (dark) | Card outline, divider |

## 4. Screen Specifications

Один блок на screen. Все API-пути — `/api/v1/`, JWT в `Authorization: Bearer`.

### 4.1 Auth: Login / Signup

| Field | Value |
|-------|-------|
| Path | `/login`, `/auth/callback` |
| Purpose | Magic-link вход через Supabase |
| Key components | Card centered, Input (email), Button «Получить ссылку», текст-инструкция |
| Primary action | POST к Supabase Auth (через SDK) → email отправлен |
| Empty state | n/a (single-state form) |
| Loading | Button → spinner + disabled, текст «Отправляем…» |
| Error | Inline `Alert variant=destructive` под Input («Не удалось отправить — проверьте email») |
| Post-auth | После клика по magic link → `/auth/callback` → POST `/api/v1/auth/me` → редирект на `/onboarding` (если `senders=[]`) или `/` (если уже подключен аккаунт) |
| Backend | Supabase Auth SDK + POST `/api/v1/auth/me` |

### 4.2 Onboarding wizard — Add first TG account

| Field | Value |
|-------|-------|
| Path | `/onboarding` (auto-redirect от первого `/auth/callback`), `/senders/new` (manual entry) |
| Purpose | За один сеанс прицепить рабочий TG-аккаунт |
| Pattern | Multi-step wizard (`<WizardSteps>`): 1) метод (phone / QR) → 2) phone+code | qr-scan → 3) 2FA (опционально) → 4) success |
| Step 1 — method | RadioGroup «По телефону» (default) / «По QR-коду». Hint: «QR — для пользователей с активной сессией в Telegram Desktop». |
| Step 2a — phone | Input phone (+7…) → Button «Отправить SMS» → POST `/onboarding/start` { phone } → возвращает `session_id`; Input «Код из SMS» (4-6 cifres) → POST `/onboarding/verify-code` |
| Step 2b — QR | POST `/onboarding/qr` → возвращает base64-PNG → `<img>` 256x256; параллельно polling GET `/onboarding/sessions/{id}` каждые 2s до status='ok' или 'expired' |
| Step 3 — 2FA | Показывается ТОЛЬКО если verify-code вернул `{error:"2FA_REQUIRED"}`; Input password (masked) → POST `/onboarding/verify-2fa` |
| Step 4 — success | Display "Аккаунт подключен" + green check + sender name + CTA «Продолжить» → `/contacts` (или назад в `/senders` если зашёл оттуда) |
| Empty state | n/a |
| Loading | Button с spinner; polling QR — Progress indeterminate под QR |
| Error states | (a) `PHONE_INVALID` → inline под phone input; (b) `CODE_INVALID` → inline + counter «Осталось попыток: N»; (c) `2FA_INVALID` → inline; (d) `SESSION_EXPIRED` → AlertDialog «Сессия истекла, начнём заново» + reset wizard; (e) `FLOOD_WAIT` → Alert warning «Слишком много попыток, подождите N сек» |
| Backend endpoints | POST `/onboarding/start`, `/verify-code`, `/verify-2fa`, `/qr`, GET `/onboarding/sessions/{id}` |
| Tone | Дружелюбно-инструктивно: «Введите номер так же, как в Telegram — с кодом страны.» |

## 5. Interaction Patterns

### 5.1 Forms

- **Validation library:** `zod` schemas, paired with `react-hook-form` через `@hookform/resolvers/zod`.
- **Validation triggers:** `onBlur` для individual fields, `onSubmit` для form-level (e.g. cross-field rules).
- **Error display:** inline `p.text-destructive.text-sm.mt-xs` под FormField. Никаких toast'ов для validation — только для API errors.
- **Submit feedback:** Button disabled + spinner + текст меняется на «Сохраняем…» / «Запускаем…». На success — Toast (Sonner) success или редирект.
- **Optimistic updates:** Для PATCH-операций которые не меняют список → optimistic via TanStack Query `useMutation` + `onMutate` cancel+set. Для destructive — нет optimistic, ждём server response.
- **Required marker:** красная `*` справа от Label.

### 5.2 Wizards (Onboarding, Campaign create, CSV import)

- Top `<WizardSteps>` показывает {step_n}/{total}, completed steps — checkmark accent.
- Buttons sticky bottom: «Назад» (outline secondary, hidden on step 1) + «Далее» (accent) или «Готово» на финальном step.
- Skip back: разрешено всегда; данные предыдущих шагов сохраняются в форме (react-hook-form state).
- Quit: «Отмена» link top-right header → AlertDialog «Прервать настройку? Введённые данные не сохранятся.»

### 5.3 Toasts (Sonner)

| Variant | Color | Auto-dismiss | Use |
|---------|-------|--------------|-----|
| `success` | success | 4s | "Кампания запущена", "Аккаунт подключен" |
| `info` | dominant + border | 5s | "Очередь обновлена" |
| `warning` | warning | 6s | "Лимиты вне зелёного коридора, но сохранено" |
| `error` | destructive | 8s | "Не удалось отправить сообщение", + Action: «Повторить» |

Position: `bottom-right`, max 3 visible, stack.

### 5.4 Loading states (4-tier policy)

1. **Initial page load** → `<Skeleton>` matching exact layout shape.
2. **In-flight mutation** → Button disabled + inline spinner. List/table — overlay opacity 60% + центральный spinner.
3. **Background refetch** (TanStack polling) → НЕ показываем индикатор (избегаем flicker).
4. **Long-running** (CSV import, contact check, campaign-enqueue tick) → `<Progress>` + штучный counter.

### 5.5 Empty states (4-element formula)

Все EmptyState ОБЯЗАНЫ иметь все 4 элемента:
1. **Icon** (lucide, 96px, `text-muted-foreground`)
2. **Heading** (Display size, обычный регистр, заканчивается без точки)
3. **Body** (1-2 предложения, объясняет «что это и зачем»)
4. **Primary CTA** (если действие возможно) или текстовая подсказка как разблокировать.

### 5.6 Error boundaries

- React `ErrorBoundary` на уровне `<AppShell>` → fallback page «Что-то пошло не так» + кнопка «Перезагрузить».
- API errors → перехват в TanStack Query `onError` global → Toast destructive с code+message.
- 401 → автоматический redirect на `/login` + ясный toast «Сессия истекла».
- 403 → отдельная страница `/forbidden` или inline `Alert` («Нет доступа к этой workspace»).
- 404 → page «Не найдено» + кнопка «На дашборд».
- 5xx → Toast destructive «Сервер недоступен. Повторите попытку.» + retry button.

### 5.7 Confirmations (destructive)

Three tiers по риску:
1. **Low risk** (отозвать ключ, удалить агента без кампаний): `AlertDialog` с двумя buttons.
2. **Medium risk** (удалить sender, кампанию, папку): `AlertDialog` + checkbox «Я понимаю последствия» обязательный.
3. **High risk** (delete-and-cascade, force=true): `<ConfirmDestructiveDialog>` с type-the-name pattern.

### 5.8 Keyboard

| Shortcut | Action |
|----------|--------|
| `Esc` | Close dialog/sheet/popover |
| `Cmd/Ctrl + Enter` | Submit form when focus в Textarea |
| `Cmd/Ctrl + K` | Open command palette (deferred to v2; кнопка disabled с tooltip "Скоро") |
| `↑ / ↓` | Navigate список в Combobox |
| `Enter` (inbox composer) | Send message |
| `Shift + Enter` (inbox composer) | New line |

## 6. Accessibility Minimums

| Requirement | Implementation |
|-------------|----------------|
| Focus visible | Все interactive — 2px outline `ring-accent` через `focus-visible:ring-2`. Никогда `outline:none` без замены. |
| Tab order | Логический — header → sidebar → main content → footer. Modal traps focus (`@radix-ui/react-dialog` делает это автоматически). |
| ARIA | Все icon-only buttons — `aria-label`. Status badges — `role="status"` + `aria-live="polite"` при изменении. Toast — Sonner поставляет `role="status"` by default. |
| Contrast | WCAG AA минимум — 4.5:1 для body, 3:1 для large text. Accent на dominant background = 8.6:1 ✓, accent на secondary = 8.0:1 ✓. |
| Form labels | Каждый Input связан с Label через `htmlFor`. Hint = `aria-describedby`. Error = `aria-invalid` + `aria-describedby`. |
| Keyboard nav | Все actions достижимы без мыши. Combobox — Radix `cmdk` обеспечивает arrow keys + Enter + Esc. |
| Screen reader | Page title (`<title>`) уникальный per route. Skip-to-content link в самом верху shell (visually hidden until focus). |
| Reduced motion | `@media (prefers-reduced-motion: reduce)` — отключить toast slide, dialog fade, sidebar collapse animation. |
| Color independence | Статусы — не только цвет, но и иконка/текст. Например, badge «лид» = green dot + текст "Лид". |
| Touch targets | Минимум 44×44px для primary buttons (a11y; не зависит от desktop-priority). |

## 7. Localization & Tone

### 7.1 Language

- **Primary:** `ru-RU` (русский). Все user-facing строки — русские.
- **i18n library:** `react-intl` или `i18next` — выбор за Lovable; ключи в `src/locales/ru-RU.json`. (Подготовка к v2 EN — не реализуем, но не хардкодим строки в JSX.)
- **Backend errors:** приходят с `code` (string enum, e.g. `SENDER_LOCK_CONFLICT`); фронт делает mapping в локализованный текст. Никогда не показываем сырой `message` из backend (он на английском).

- **Регистр:** формальный «вы» (B2B SaaS, корпоративный клиент). НЕ «ты».

- **Примеры:**
  - ✓ «Запустите первую кампанию»
  - ✗ «Запусти кампанию, погнали!»
  - ✓ «Не удалось отправить сообщение. Проверьте подключение аккаунта.»
  - ✗ «Упс, что-то сломалось :(»
