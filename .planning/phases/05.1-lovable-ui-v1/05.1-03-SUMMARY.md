- **POST /api/v1/campaigns/{id}/stop** added at `app/routers/campaigns.py:650` — one-line alias of `finish_campaign(campaign_id, ctx, db)`. Same response shape, same lifecycle transition guard (running|paused → done, terminal). UI labels say "Stop" (UI-SPEC §5.4/§5.6); backend has historically been "finish" since Phase 4. Alias-not-rename preserves Phase 4 `test_campaign_router.py` without churn.
- **POST /api/v1/campaigns/auto-fill** added at `app/routers/campaigns.py:385` — v1 stub returns canned defaults `{name: "Untitled campaign", audience_hints: "", primary_goal: "book_meeting", success_criteria: "", tools: []}` (UI-SPEC §5.5). Request body accepts `{brief: Optional[str]}` so the wire format already matches what v2 LLM-driven implementation will need; brief is currently ignored. `auth_dep` enforced so the endpoint surface isn't enumerable.
- **4 v2 fields** (`audience_hints`, `primary_goal`, `success_criteria`, `webhook_url`) wired through `create_campaign` ORM constructor, `patch_campaign` HttpUrl→str coercion loop + setattr propagation, `_campaign_to_response` helper, and `duplicate_campaign` source-copy block.

### Task 2 — Sender lifecycle (commit `9cbe8f1`)

- **POST /api/v1/senders/{slug}/pause** added at `app/routers/senders.py:424` — active → paused with Phase 4 `_check_sender_not_in_running_campaign` guard preserved (sender locked in running campaign → 409 `SENDER_USED_BY_RUNNING_CAMPAIGN`). Idempotent: already-paused → 200 with current state.
- **POST /api/v1/senders/{slug}/resume** added at `app/routers/senders.py:461` — paused → active. Idempotent: already-active → 200.
- Both endpoints return `SenderCreateResponse` (sender + warnings[]) for shape parity with `POST /senders` and `PATCH /senders/{slug}` — Lovable can reuse the same response handler.
- Strict guard: warmup→pause / banned-state→pause both rejected with 409 INVALID_TRANSITION (encourages bug surfacing — only specific known transitions allowed).
- Existing **PATCH /senders/{slug}** lifecycle path (line 329) preserved — additive, not replacement. UI uses /pause + /resume for one-button row actions; advanced flows still use PATCH with typed body.
- **Tests:** 1 new file / 9 cases — pause active / pause paused idempotent / resume paused / resume active idempotent / sender-lock 409 / cross-workspace 404 × 2 / warmup→pause INVALID_TRANSITION / PATCH lifecycle regression.

- **12 v2 fields** wired through `app/routers/agents.py`:

  - `update_agent` adds 12 conditional setattr blocks following the existing per-field PATCH style.
  - `duplicate_agent` copies all 12 v2 fields alongside the 6 legacy ones (parity-on-fork).
  - `_agent_to_response` propagates all 12 v2 fields straight from ORM columns (None for pre-05.1 rows).
- **ai_engine COALESCE** at `app/services/ai_engine.py`:
  - **Primary SELECT** (`get_context_for_conversation`, line 161): `COALESCE(a.who_is_agent, a.system_prompt) AS system_prompt`, `COALESCE(a.qa_pairs::text, a.faq::text)::jsonb AS faq`, `COALESCE(a.company_knowledge, a.company_info) AS company_info`, `COALESCE(a.knowledge_base, a.product_info) AS product_info`. Ordinal positions unchanged so the dict-build at lines 175-194 still works (it reads `row.system_prompt`, `row.company_info`, etc. — named access on Row, no positional dependency).
  - **Fallback SELECT** (`AIEngine.get_context`, line 391): `COALESCE(who_is_agent, system_prompt) AS system_prompt`, `COALESCE(company_knowledge, company_info) AS company_info`. (No `a.` prefix — different table alias context, single-table SELECT.)
  - **build_system_prompt and build_tools NOT modified** — they continue reading the merged context dict keys (`system_prompt`, `company_info`, `product_info`). The contract is that the SELECT now returns *better* values (new wins) but the dict keys stay legacy-named for backward compat with the prompt builder. `git diff app/services/ai_engine.py | grep -E "^[+-].*def build_(system_prompt|tools)"` returns 0.
- **JSONB COALESCE caveat:** for `faq`, both `qa_pairs` and `faq` are JSONB. Postgres doesn't apply `COALESCE` directly across two JSONB columns without explicit cast (CAST inference fails when one side is NULL). Solution: `COALESCE(a.qa_pairs::text, a.faq::text)::jsonb AS faq` — text-cast both sides, then cast result back to JSONB. Documented in the SQL comment block.

## How COALESCE choice (new > legacy) was tested

Three cases in `tests/test_phase5_1_agents_v2_router.py` exercise the COALESCE matrix using a raw SELECT that mirrors the engine's SQL exactly:

- **legacy-only fixture** — `test_ai_engine_coalesce_legacy_only_agent`: agent created with `system_prompt='LEGACY_PROMPT_TEXT'`, `company_info='LegacyCo'`, `product_info='LegacyProduct'`, all v2 cols NULL → COALESCE returns the legacy values (asserts `row.system_prompt == 'LEGACY_PROMPT_TEXT'`).
- **dual-set fixture** — `test_ai_engine_coalesce_new_wins_when_both_set`: agent created with legacy values, then UPDATEd to set `who_is_agent='NEW_PROMPT'`, `company_knowledge='NewCo'`, `knowledge_base='NewProduct'` → COALESCE picks the new values (asserts `row.system_prompt == 'NEW_PROMPT'`).
- **new-only fixture** — `test_ai_engine_coalesce_new_only_no_legacy`: agent created with legacy cols NULL, then UPDATEd to set only the new cols → COALESCE picks the new values (asserts `row.system_prompt == 'NEW_ONLY_PROMPT'`).

This three-pronged matrix confirms the SELECT behaves correctly across all three states an agent row can be in after migration 018 ships.
