## Accomplishments

### Task 1 — `app/routers/analytics.py` extended with `GET /funnel` + `GET /llm`

- **`GET /funnel?scope=workspace|campaign|agent|sender&id=...`** returns 5 stage counts: `sent / replied / engaged / lead / handoff`.
  - `sent` = `COUNT(*)` from `messages JOIN conversations` with `m.direction='outbound'` (Phase 5 C-01 source-of-truth — covers queue worker, listener self-checks, and UI manager-send D-04).
  - `replied` = `COUNT(DISTINCT m.conversation_id)` with `m.direction='inbound' AND m.sent_by='contact'`.
  - `engaged` = `COUNT(*) FROM (SELECT ... HAVING COUNT(*) >= 2)` — distinct conversations with **≥ 2 inbound contact messages** AND `status NOT IN ('lead','handoff','finished','bot_ignored')`. **Definition LOCKED in code per RESEARCH Pitfall 5** (the #1 drift risk in the phase).
  - `lead` = `COUNT(*) FROM conversations WHERE status='lead'` (strict EQ; Pitfall 9 — does NOT include `'finished'`).
  - `handoff` = `COUNT(*) FROM conversations WHERE status='handoff'` only — explicitly **excludes** `'manual'` (the human-driven takeover is not a funnel progression event; UI-SPEC §8.3 maps both to "Manager" mode for inbox display but the funnel locks to the AI-triggered signal).
  - `bot_ignored` conversations are excluded from **every** count (Phase 5 Pitfall 8 carry-over).
  - Cross-workspace `id=` → 404 silent (`{code: "CAMPAIGN_NOT_FOUND" / "AGENT_NOT_FOUND" / "SENDER_NOT_FOUND"}`); does not leak existence of other-workspace resources.
  - Invalid `scope` (FastAPI Literal validation) → 422.
  - Missing `id` for non-workspace scope → 422 `{code: "ID_REQUIRED"}`.
- **`GET /llm?scope=workspace|campaign&id=...&since=1d|7d|30d|90d`** returns `total_calls / avg_latency_ms / prompt_tokens / completion_tokens / total_tokens / spend_usd_cents`.
  - `avg_latency_ms` is `Optional[int]` — `None` when no `llm_calls` rows match the filter (empty window).
  - `spend_usd_cents` is **always 0 in v1** (per-model pricing deferred to v2 — see RESEARCH §"Backend Gap Map"). The field is reserved in the response shape so v2 can land pricing without breaking the contract.
  - `since` accepts only `1d/7d/30d/90d` (Literal validation → 422 on invalid).
  - `scope` accepts only `workspace|campaign` for `/llm` (agent/sender scopes are out of scope — Pitfall 8 enforcement).
  - SQL uses `NOW() - (:days || ' days')::INTERVAL` with `:days` bound (no f-string interpolation of user input).

### Task 2 — `app/routers/telemetry.py` NEW + registered in `app/main.py`

- **`POST /api/v1/telemetry/events`** with body `{event, props, event_id?, client_timestamp?}`.
  - Whitelist check first: unknown event → **400 `{code: "UNKNOWN_EVENT"}`** (contract error — typos / agent hallucinations get caught at the edge, never pollute the table).
  - Whitelisted event → **202 Accepted** with body `{accepted: True, event_id: "<uuid>"}`.
  - Idempotent: `event_id` is client-supplied UUID PK (decision from 05.1-01); `INSERT ... ON CONFLICT (event_id) DO NOTHING` makes navigator.sendBeacon retries safe — same `event_id` POST'd N times → only 1 row in `telemetry_events`. Both initial POST and dup retries return 202.
  - Server-generates `event_id` when the client omits it (`Optional[UUID]` per 05.1-01 schema).
  - Security: `logger.info` carries only `workspace_id / event / event_id` — `body.props` is **never logged** (may contain user PII or webhook tokens).
- **`GET /api/v1/telemetry/core-value`** returns `{time_to_first_campaign_seconds, signup_at, first_launch_at}`.
  - SQL: `WITH t AS (...)` with two workspace-scoped subqueries (`MIN(server_ts)` for `signup_completed` + `MIN(server_ts)` for `campaign_launched`), then `EXTRACT(EPOCH FROM (first_launch_at - signup_at))::INT`.
  - All three fields are `Optional` — return `null / null / null` when the workspace has no signup yet, and `t1 / null / null` when signup exists but no launch (UI renders "—").
  - Workspace isolation is **structurally enforced at the SQL level**: both subqueries filter `WHERE workspace_id = :wid`. No JOIN to a global table → cross-workspace leakage is impossible by construction.
- `_EVENT_WHITELIST` constant holds **17 events** (15 from UI-SPEC §9 numbered list + 2 derived: `dashboard_viewed`, `custom_tool_added`).
  - Sanity test `test_ingest_whitelist_contains_all_15_events` asserts the exact set membership — any drift surfaces in CI before reaching prod.

## Decisions Made

See `key-decisions:` in frontmatter for the canonical list. Highlights:

1. **engaged-stage definition locked in code (Pitfall 5).** The plan's `<behavior>` block specified `COUNT(DISTINCT conversation_id WHERE >= 2 inbound contact msgs AND status NOT IN ('lead','handoff','finished','bot_ignored'))` and the SQL implements it exactly. The `grep -c "NOT IN ('lead','handoff','finished','bot_ignored')"` check returns 2 in `app/routers/analytics.py` (engaged query + that fact is asserted in an acceptance criterion). Drift in this clause would silently change Sankey funnel shape across the entire product — locking the SQL string is the cheapest way to prevent that.
2. **Funnel handoff stage = status='handoff' only.** UI-SPEC §8.3 specifies the inbox renders both `'handoff'` and `'manual'` conversations under the "Manager" label, but `'manual'` is a human-driven takeover (Phase 5 D-04) — not a funnel-progression signal. Including it would conflate UI inbox display with funnel semantics. Lock to `'handoff'` (the AI-triggered signal) only.
3. **spend_usd_cents = 0 v1 stub.** Per-model pricing requires a pricing table + currency conversion + tracking for `prompt_tokens` vs `cached_input_tokens` (gpt-4o-mini has cache tier) — deferred to v2. The field stays in the response shape so the frontend can render a placeholder ("—" or "$0.00") without breaking the contract when v2 lands real pricing.
4. **Workspace isolation in /core-value via subqueries, not JOIN.** Both `MIN(server_ts)` subqueries individually filter `WHERE workspace_id = :wid`. There is no path for one workspace's signup time to influence another workspace's delta — the structure of the SQL makes cross-workspace leakage impossible by construction, not merely "not exercised in the current tests".
5. **404 silent on cross-workspace ids.** Following the Phase 5 pattern (`_ensure_campaign_in_workspace` returns 404, not 403): we don't leak the existence of other-workspace resources via differential error codes. Same treatment in `/funnel` prequery and `/llm` prequery.
