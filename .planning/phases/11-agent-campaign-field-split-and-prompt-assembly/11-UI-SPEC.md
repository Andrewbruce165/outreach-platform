## Spacing Scale

The aimly kit is spacing-consistent on a 4px base. Declared values (multiples of 4):

| Token | Value | Usage in this phase |
|-------|-------|---------------------|
| xs | 4px | Icon↔text gaps, inline chip padding |
| sm | 8px | Field-group gaps, stage-card internal gaps (`.col` gap, `.field` label↔hint) |
| md | 16px | Default gap between fields in a form (`.ob__form` gap 14 → round to 16 for new groups) |
| lg | 24px | Step body padding / section padding (`.tb` 24px horizontal, `.ct__mainHead` 18–24) |
| xl | 32px | Major layout gaps between form sections |
| 2xl | 48px | Reserved — not expected in dense forms |
| 3xl | 64px | Reserved — page-level only |

**Exceptions (carried from existing kit — keep verbatim, do NOT "fix"):**
- Form-control height `38px` (`.input` / `.select`), textarea min-height `80px` — established control sizing.
- Button height `36px` (`.btn`), small `30px` (`.btn--sm`).
- Existing wizard rhythm uses 14px gaps (`.ob__form`, `.field` 6px) — match neighbors; do not mix 14 and 16 within the same form block. **When in doubt, copy the adjacent existing field's spacing.**

## Typography

Driven by aimly tokens (base `font-size: 14px`, `line-height: 1.45`). 4 roles, **exactly 2 weights — `400` and `600`**:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body / input text | 13–14px | 400 | 1.45 (controls) / 1.5 (textarea) |
| Field label | 12px | 600 | 1.45 (`.field__label`) |
| Field hint / helper | 11.5px | 400 | 1.4 (`.field__hint` / `.muted`) |
| Section / step title | 17–18px | 600 | 1.2 (`.ob__title` / `.tb__title`) |

**Weights:** exactly two — `400` (body and hints) and `600` (every emphasized element: labels, section/step titles, pills, the stage-number badge). There is no third weight.

> **Legacy-CSS note (not a third weight):** some existing kit classes (`.field__label`, `.pill`) ship at `font-weight: 500` in `aimly.css`. Per the contract, all emphasis is `600`; the executor MUST treat 600 as the single emphasis weight for any new markup. Pre-existing `500` rules in untouched legacy CSS may stay as-is, but no new code introduces 500 — when a new element needs emphasis, use 600.

**Exception:** stage-editor stage-number badge and `.pill` are micro-labels at 11–11.5px; they take the `600` emphasis weight (no separate weight value introduced).

## Color

60/30/10 derived from the aimly token set (light Telegram theme). New code references **tokens**, never raw hex.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#f4f5f7` (`--bg-soft`) / `#ffffff` (`--bg`,`--surface`) | App canvas, form surfaces, inputs |
| Secondary (30%) | `#f7f8fa` (`--surface-2`) + `#ebedf0` (`--border`) | Cards, stage-card backgrounds, dividers, sidebar |
| Accent (10%) | `#3390ec` (`--tg-blue`) | See reserved-for list below |
| Destructive | `#e13b30` (`--danger`) / `#fde8e6` (`--danger-soft`) | Destructive actions only (remove stage, delete agent) |

**Accent (`--tg-blue`) reserved for — explicit list, do NOT broaden:**
- Primary CTA buttons (`.btn--primary`: "Сохранить", "Запустить", "Далее").
- Active wizard step + active selected option (`.is-active` agent card / `.ob__step.is-active`).
- Focused form control ring (`.input:focus` → `box-shadow rgba(51,144,236,.12)` + `border-color --tg-blue`).
- Selected/active list item & soft pills (`.pill--blue`, `.btn--soft`).
- The "+ Добавить стадию" affordance and stage reorder controls (secondary/ghost emphasis, blue on hover).

**Semantic-color notes for this phase:**
- `--warning` (`#f5a623` / `--warning-soft`) for the green-corridor / rate hints — **unchanged**, not introduced here.
- `--ai-purple` (`#8774e1`) is reserved for AI/auto-fill affordances (Brief "expand with AI" / `.ai-shimmer`). The Brief auto-fill button MAY use purple accent to signal "AI-generated draft" — consistent with existing AI motif. Do not use purple for ordinary fields.

## Interaction Contracts

### Stage editor ("Ход разговора", `dialogue_flow`)
- **JSON shape:** `[{ "title": string, "instruction": string }]` (RESEARCH rec; D-04). `instruction` required, `title` optional but encouraged.
- **Empty state (DEFAULT — recommended):** show an empty zone with hint text «Опишите 3–5 стадий разговора: что делать на каждом шаге.» + a single «+ Добавить стадию» button. Do NOT auto-seed template stages (keeps the form honest; no fake content reaching the prompt). *(Researcher default — confirm with user at plan time if desired.)*
- **Add:** appends an empty stage card, focus moves to its title input.
- **Remove:** `X` icon-button (danger on hover, `--danger-soft`, `aria-label="Удалить стадию"`); no confirmation needed for an empty/just-added stage; confirmation NOT required (cheap to re-add). For a stage with content, a lightweight inline undo via toast is acceptable but optional.
- **Reorder:** up/down chevrons (`aria-label="Переместить вверх"` / «вниз»); first card's "up" and last card's "down" are disabled. Array order == prompt order (D-06).
- **Validation:** stages with empty `instruction` are dropped on save (not sent to backend); surface no hard error, just don't persist blanks.

### Response-speed control (`response_speed` + `response_delay_seconds`)
- **Control (DEFAULT — recommended):** `.select` with 4 options (matches existing `voice_baseline` select pattern), and when `manual` is chosen, reveal a `.input number` («Задержка, сек») directly beneath with a `.field__hint`. *(Researcher default; segmented control is an acceptable alternative — confirm at plan time.)*
- **Options + copy:** Мгновенно (`instant`) / Как человек (`human`, default) / Медленно (`slow`) / Вручную (`manual`).
- **Default selection:** `human` (back-compat with current debounce behavior — RESEARCH).
- **Manual field:** integer seconds, min 0; hint «Фиксированная задержка перед ответом ИИ.» Only rendered when `manual`.

### Arguments & facts guard hint (`arguments_facts`)
- **DEFAULT — recommended:** render a `.field__hint` under the textarea: «ИИ использует только эти факты и не выдумывает остальное.» This mirrors the backend anti-hallucination guard (D-12) so the user understands the behavior. The guard text itself is added to the prompt backend-side, not by the UI.

### Brief auto-fill (`/campaigns/auto-fill`)
- **Unchanged behavior, clarified contract:** auto-fill populates **structural fields only** (name, audience_hints, primary_goal, and — post-migration — the lead-signal hint). The raw brief text is NOT a prompt source (D-15). The auto-fill button keeps the AI/purple affordance (`Sparkles` icon, `.ai-shimmer` allowed during loading). After auto-fill, populated fields remain fully editable.
- **Note for executor:** the existing `autoFillMut` reads `success_criteria` from the response — after MIG-03 the auto-fill backend response and the form field it targets must move to the lead-signal hint. Keep the UI mapping in sync with the renamed field.
