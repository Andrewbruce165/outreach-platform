<objective>
Close the remaining Phase-14 prevention gap surfaced by the 14-06 spike (Q3): one
batch (≤ burst_cap 30) is safe, but the worker chains batch-after-batch on the SAME
checker with only a 5s poll between them, so the cumulative burst crosses the ~45-50
throttle onset within ~2 batches and the checker gets throttled. Add a benign
per-checker POST-BATCH REST so a checker rests after each batch and the existing
rotation alternates the two healthy checkers (≈2x throughput, no parallel execution).

This is the guarded-re-activation PREREQUISITE the 14-06 GO verdict authorised. It is
CODE ONLY: a new durable rest column + worker gate + after-batch UPDATE + RED-first
tests. It does NOT re-activate the parked checkers and does NOT drain the 14k — those
remain a separate, user-gated ops step.
</objective>
