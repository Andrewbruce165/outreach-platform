## Идея

Дать клиенту тонкую настройку rate limits на уровне workspace с UI "зелёного коридора" — рекомендованные значения + warning при выходе за них.

## Скоуп

- **Текущее состояние:**
  - Per-sender лимиты уже в БД (Phase 02 plan 02-02: `senders.rate_per_min/rate_per_hour/rate_per_day`)
  - Дефолты при создании sender'а захардкожены — 4/20/150
  - "Зелёный коридор" нигде не выведен в UI, нет warning'ов
- **Что добавить:**
  - `workspaces.default_rate_per_min/hour/day` — дефолт для новых sender'ов workspace (overridable per-sender)
  - UI: Settings → Anti-Spam → Rate Limits
    - Поля с подсказками: "рекомендовано 4/20/150 — эмпирически безопасно для warm аккаунтов"
    - Warning при выходе за коридор + кнопка "Я понимаю риски"
    - История изменений (audit log) — кто и когда менял
  - Workspace-level настройка расписания по умолчанию (`default_tz`, `default_h_start`, `default_h_end`, `default_days_mask`) — применяется при создании новой кампании

## Зачем

1. Клиент хочет тонко настроить под свой пайплайн (например, "наша ниша терпит 7/40/200" — он готов рисковать)
2. Без UI клиенту приходится дёргать поддержку для каждой настройки
3. "Зелёный коридор" — образовательный элемент: показывает что 4/20/150 не случайно, а эмпирически

## Зависимости

- Per-sender override уже работает (Phase 02 plan 02-02)
- Per-campaign schedule уже работает (Phase 04 plan 04-03)
- Workspace-default = финальный layer над этими двумя

## Альтернатива

Оставить hardcoded "зелёный коридор" — пользователь не может изменить. Безопаснее, но негибко.

## Открытые вопросы

- Аудит-лог кто и когда менял rate limits — нужен или нет?
- Жёсткий потолок (например, 30 msg/min) или абсолютная свобода?
- Connection с REPLY-01 (debounce ответов) — оба в "anti-spam" cluster, единый UI?
